# 🔥 1. The MOST IMPORTANT pattern (everyone does this)

Across almost all real projects:

```text
scrape → filter → dedupe → notify → human acts
```

Not:

```text

```

# 🧠 3. Key architecture lessons (from ALL repos)

## 1. **Store seen listings**

Every project does this

```python
if listing_id not in database:
    send_alert()
```

👉 Without this → spam + chaos

---

## 2. **Speed > completeness**

Example:

* Some bots run every **2 minutes**
  ([GitHub][5])

👉 Why?
Because:

> “applying as soon as they're listed boosts your chances”
> ([Reddit][6])

---

## 3. **Telegram is standard**

Almost every repo uses:

* Telegram
* Slack
* Email

👉 Telegram wins for speed

---

## 4. **Deduplication is ALWAYS needed**

Because:

* Same house appears on:

  * Pararius
  * Funda
  * Rentfinder
  * Huislijn

👉 If you don’t dedupe → noise

---

## 5. **Human action is required**

No serious project:

* auto-applies
* auto-spams landlords

👉 They ALL:

* notify
* you act

---

# ⚠️ 4. Reality of scraping (important)

From scraping best practices:

* Sites change often
* Scrapers break
* Too many requests → blocked
  ([GitHub][7])

👉 So:

* Keep it simple
* Keep it light
* Don’t rely on fragile selectors

---

# 🧠 5. Eindhoven-specific insight (important for your bot)

From NL housing projects + discussion:

* Funda alerts = too slow (daily emails)
* Real bots notify instantly
* Good listings gone fast

👉 Meaning:

```text
5-minute delay = acceptable
1-minute delay = competitive edge
```
